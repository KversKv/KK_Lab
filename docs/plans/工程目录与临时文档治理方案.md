# 工程目录与临时文档治理方案

> 日期：2026-11-06  
> 范围：仓库根目录与历史临时文档；不调整源码模块边界。

## 审查结论

根目录混杂了职责明确的源码模块、本地环境、构建缓存和临时资料。源码目录本身大多对应独立架构职责，不适合为了减少目录数量而合并；主要问题是可再生成产物和临时文件缺少统一入口，且文档目录名 `NewPlan` 无法表达长期用途。

初始盘点有 31 个一级目录，其中包括本地缓存、PyInstaller 中间产物和旧 `Temp/`。清理后保留 25 个有职责的一级目录。文档还分散在 `docs/` 的计划、用户手册、技术参考与运行期 AI 记忆之间，生命周期边界不清。

## 目标结构与处置原则

| 内容 | 目标位置 / 决策 | 原则 |
|---|---|---|
| 工程计划、设计稿 | `docs/plans/` | 使用主题化文件名，计划用完后更新结论与进度，不另建含义模糊的目录 |
| 文档入口 | `docs/README.md` | 明确每类文档的用途、生命周期和临时资料规则 |
| DLP 文件及测试数据 | `Temp_Docs/` 中保留原相对路径 | CSV、XLSX、PDT、PDF 不进入 Git 跟踪路径 |
| 历史临时资料 | `Temp_Docs/archive/` 的分类子目录 | 不确定是否有复用价值时归档而非删除 |
| 构建中间产物、Python 缓存 | 删除后按需生成；忽略规则纳入 `.gitignore` | 确认没有运行中的 Python/PyInstaller 任务后清理 |
| 发布交付物、本地开发环境 | 保留 `dist/`、`.venv/` | 有实际发布/开发用途，不作为缓存删除 |
| 源码和 IDE 配置目录 | 保持现状 | 按职责保留，不做纯粹的目录数量优化 |

## 后续验收口径

1. 根目录不再出现历史 `Temp/`、PyInstaller `build/` 和 Python 工具缓存；这些目录可由本机工具按需生成。
2. `docs/plans/` 与文档导航链接有效，仓库内不保留旧计划目录的活动引用。
3. 临时 DLP 文件继续放在被忽略的 `Temp_Docs/`，原路径镜像和有效验证产物不被清理。
4. 目录新增、删除或重命名后同步维护 `DIRECTORY_STRUCTURE.txt` 与 `docs/README.md`。
